# Скриншоты README

Снимки делает отладочная сборка в демо-режиме с выдуманными данными. Настоящее приложение пользователя не трогается,
перезапускать его не нужно.

## Порядок

1. Собрать приложение вне песочницы proxy командой `agentmeister host-run agentmeister-app-build`. Внутри песочницы
   `swift build` падает.
2. Если менялись данные демо (`docs/screenshots/make_demo.py`), запустить `/usr/bin/python3 docs/screenshots/make_demo.py`.
   Он пишет JSON для экранов и текст вкладок в двух вариантах, `claude.txt` для темной темы и `claude-light.txt`
   для светлой, на английском в `demo/` и на русском в `demo/ru/`. Новый текст, который видно на снимке,
   оборачивать в `t("english", "русский")`. Иконки проектов перерисовывает `/usr/bin/python3 docs/screenshots/draw_icons.py`.
3. Пробный прогон в папку сессии, чтобы не затереть снимки в репозитории,
   `/usr/bin/python3 docs/screenshots/shoot.py --out <scratchpad>/shots main`. Открыть PNG через Read и
   посмотреть обе темы.
4. Если все в порядке, `/usr/bin/python3 docs/screenshots/shoot.py` снимает в репозиторий. Без аргументов
   снимаются сцены README (main, new-session, project, settings) в обеих темах и на обоих языках, файлы
   `<сцена>-dark.png` и `<сцена>-light.png` в `docs/screenshots` и русские в `docs/screenshots/ru`. Один язык
   снимает `--lang en` или `--lang ru`. Для одной темы есть `--theme dark` и `--theme light`. Другие сцены (rail,
   settings-modes, about, headsup, subtasks и т. п.) перечислены в `SCENES` в `shoot.py`.
5. Каждый снимок открыть через Read и сверить с настоящим окном. Для сверки можно снять настоящее окно
   (`agentmeister shot Agentmeister` или инструмент `window_screenshot`), но в нем личные данные пользователя:
   смотреть только для сравнения, в репозиторий не класть.
6. Обновить ссылки в `README.md` (английские снимки) и `README.ru.md` (из `docs/screenshots/ru`). Снимки вставлены через `<picture>`: темный в
   `<source media="(prefers-color-scheme: dark)">`, светлый в `<img>`, так GitHub показывает тему читателя. Ряд со
   светлым и темным главным окном рядом показывает обе темы сразу. Новый снимок добавлять так же и в оба README.

## На что смотреть

- Демо должно выглядеть как настоящее окно. Если в приложении появилась новая панель, строка или поле, а в демо
  оно пустое, данные добавляются в `make_demo.py`, а поведение демо в `app/Sources/Agentmeister/Demo.swift`
  (только отладочная сборка).
- Текст вкладок повторяет нынешний Claude Code: запрос пользователя строкой `❯ текст` на серой подложке во всю
  ширину (по ней приложение находит запросы), поле ввода между двумя линиями `─`, строка состояния promptsill
  с отступом в две колонки, у diff красная и зеленая подложка. Если Claude Code меняет вид, поправить функции
  `ask`, `box`, `diff`, `tool` и цвета `PALETTES` в `make_demo.py`.
- Ширина текста вкладки задана `W` в `make_demo.py`. Если терминал в окне стал уже или шире, строки переносятся
  или линии не доходят до края, тогда подобрать `W` по снимку.
- Кнопки окна. Неактивное окно снимается с серыми кнопками. `shoot.py` считает цветные кнопки
  (`lights.js colors`), снимает снова и в темной теме перекрашивает серые по образцу `lights.png`. Светлые серые
  кнопки почти сливаются с фоном, поэтому после съемки проверить все снимки:
  `for f in docs/screenshots/{,ru/}*-*.png; do echo $f $(osascript -l JavaScript docs/screenshots/lights.js $f colors); done`.
  Должно быть 3, у new-session 2. Кнопки должны стоять внутри карточки проектов, а не на ее скругленном углу. Под листом новой сессии macOS гасит кнопку закрытия и в настоящем окне, на этом снимке
  она остается серой.
- Тема и раскладка задаются аргументами (`-appearance`, `-terminal.colors window`, `-layout.*`), а не
  настройками демо, поэтому снимок не зависит от прошлых запусков. Новая настройка, от которой зависит вид,
  добавляется туда же в `shoot.py`.
- Длинные русские названия могут не влезть туда, где английские помещаются (вкладки, плитки действий). Если
  на снимке появились стрелки прокрутки вкладок, сократить названия в `make_demo.py`.
- Пока идет съемка, мак лучше не трогать, окно демо должно быть активным.

## Перед PR

Старые снимки, которые больше не нужны, удалить через `git rm`. Проверить, что README не ссылается на
несуществующие файлы, `grep -o 'docs/screenshots/[a-z-]*\.png' README.md README.ru.md | sort -u` и `ls` по ним.
Этот навык лежит в `.claude/`, которую глобальный gitignore прячет, поэтому изменения в нем добавлять через
`git add -f`.
