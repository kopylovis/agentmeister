# Agentmeister для Mac

Окно SwiftUI вместо iTerm2. Слева проекты из папки проектов и их последние сессии, справа вкладки на
[SwiftTerm](https://github.com/migueldeicaza/SwiftTerm), в каждой `agentmeister <проект> -n -x` запускает Claude
Code или Codex с proxy и sandbox-exec, как во вкладке терминала. Боковая панель, панель инструментов и
панель сессии системные, в macOS 26 они рисуются жидким стеклом. Язык берется тот же, что у меню agentmeister.

Нужны macOS 26 и Xcode 26.

## Запуск

Из обычного терминала, не из proxy-сессии: у SwiftPM своя песочница macOS, и внутри sandbox-exec она падает.

```sh
cd ~/Developer/agentmeister
make app                                  # app/build/Agentmeister.app
open app/build/Agentmeister.app
```

`app/bundle.sh` собирает `.app` из готового бинарника: Info.plist с bundle id `com.agentmeister.app` и схемой
ссылок `agentmeister://`, иконка из `share/agentmeister/icon.png`, подпись первым сертификатом Developer ID
Application или Apple Development из связки (или `AGENTMEISTER_SIGN=<имя>`, без сертификата ad-hoc).
Разрешения macOS привязаны к подписи, поэтому одна подпись между сборками бережет их. Для отладки хватает
`cd app && swift run Agentmeister`.

Из proxy-сессии агент собирает приложение через `agentmeister host-run agentmeister-app-build`.

## Как устроено

- `Backend.swift` опрашивает в два темпа. Статусы открытых сессий он читает сам из
  `~/.claude/sessions/<pid>.json` раз в 2 секунды. Полный `agentmeister app-state` (JSON с проектами,
  сессиями, proxy и режимами) идет при запуске, когда окно становится активным, раз в минуту и после смены
  статуса сессии. `app-state` берет заголовки неизменившихся сессий из кэша `~/.cache/mnrh/app-state`, один
  запуск стоит около 0.1 секунды процессора. Окружение и PATH берутся из `zsh -l`,
  потому что у приложения из Dock PATH без Homebrew.
- `Tabs.swift` держит вкладки. Вкладка узнает свою сессию Claude Code по дереву процессов: процесс из
  `~/.claude/sessions/<pid>.json` должен быть потомком shell этой вкладки. Так у вкладки появляется статус
  "ждет ответа" и id сессии для перезапуска.
- Вкладки сохраняются в `~/Library/Application Support/Agentmeister/tabs.json` при каждом изменении и
  открываются снова при следующем запуске. Сессия Claude Code продолжается с того же места. Сессию, открытую
  в другом окне, приложение не трогает, а пустую, без ответа Claude, начинает заново.
- Окно "Сессии" (⇧⌘O, кнопка с книгами в панели инструментов) показывает все сессии всех проектов, ищет по
  переписке тем же индексом, что `agentmeister sessions search`, и показывает последние сообщения выбранной
  сессии. Оттуда сессию можно продолжить во вкладке или удалить. Данные идут через `agentmeister app-state
  search` и `app-state read`. Окно, запрос и выбранная сессия возвращаются после перезапуска.
- Окно "Статистика" (⇧⌘U, кнопка с графиком в панели инструментов) показывает то же, что `agentmeister usage`:
  активное время, сессии, запросы и токены за 7 дней, 30 дней или все время, график по дням и по проектам,
  таблицу проектов и самые тяжелые сессии с кнопкой "Продолжить". Данные идут через `app-state usage`.
- Сессию, которая открыта в другом окне (iTerm2, Terminal, второй Agentmeister), приложение не продолжает,
  а предупреждает: второй Claude на той же переписке перемешал бы ответы.
- `/restart`, `/forget`, `/fresh` и `/slim` работают внутри вкладки. Вкладка ставит `MNRH_RESTART_HOOK=2`, как
  хук `share/agentmeister/restart.zsh`, и после выхода agentmeister выполняет задания из
  `~/.cache/mnrh/restart/<tty>` через `restart_job.py take` и `run`.
- Настройки (⌘,) показывают proxy, белый список host-run, уведомления с Telegram и телефоном, режимы с
  правилами guard, агентов и проверки `agentmeister doctor`. Данные идут через `app-state settings` и
  `app-state doctor`, изменения теми же командами, что в CLI (`notify`, `guard skip`, `proxy restart`).
  Шаги, которым нужен терминал (`proxy setup`, `lid setup` с sudo, подключение бота), открываются
  служебной вкладкой в главном окне.
- Когда подписок proxy больше одной (`agentmeister proxy add`), в листе новой сессии, в листе параллельной
  задачи и в меню маршрута на экране проекта появляется выбор подписки. По очереди значит `-x` (каскад), а
  только одна значит `--proxy=<имя>`. Подписку новых сессий по умолчанию выбирают в Настройки → Proxy, она
  хранится там же, где выбор в меню терминала (`proxy remember vps:<имя>`). Вкладка помнит свою подписку
  в tabs.json, а терминал из нее идет через `proxy run --via <имя>`.
- Уведомления "Claude ждет" знают вкладки приложения. Вкладка передает свой id в `AGENTMEISTER_TAB`, окно
  пишет в `~/.cache/mnrh/app/front.json`, какая вкладка выбрана и активно ли оно, и хук не шлет уведомление о
  вкладке, на которую ты смотришь. Клик кладет запрос в `~/.cache/mnrh/app/focus.json` и открывает
  `agentmeister://focus?tab=<id>`, приложение выбирает вкладку и выходит вперед.
- Мастер первого запуска открывается сам один раз и снова из меню Help. Он показывает агентов, proxy, вход
  (`claude auth login` и `codex login` через `agentmeister proxy run`), режимы и `setup`. Признак входа
  `app-state settings` берет из файлов самих агентов, токены не читает.
- `Views.swift` рисует окно, `Strings.swift` хранит тексты на русском и английском.

## Обновления

Релизная сборка обновляется через Sparkle, как tossling desktop. Раз в день она читает
`https://github.com/kopylovis/agentmeister/releases/latest/download/appcast.xml`, скачивает новую версию и ставит ее при
выходе из приложения, чтобы не остановить агентов во вкладках. Скачанную версию сразу можно поставить из меню
Agentmeister, пункт "Перезапустить и обновить", вкладки вернутся сами.

Обновления включаются только у сборки с подписью Developer ID, если в `app/sparkle-public-key` лежит публичный ключ.
Секретная половина живет в связке ключей Mac под именем agentmeister. Ее создает один раз
`generate_keys --account agentmeister` из архива Sparkle (`app/build/cache/sparkle-2.10.0/bin`), резервную копию делает
`generate_keys --account agentmeister -x <файл>`, ее место в менеджере паролей. Без этого ключа подписать
следующее обновление нечем, и установленные копии придется обновлять вручную через DMG. `release.sh` проверяет, что
ключ в связке совпадает с `app/sparkle-public-key`, подписывает DMG и кладет `appcast.xml` рядом с ним, оба файла
уходят в релиз на GitHub.

## Горячие клавиши

⌘, настройки, ⌘K палитра команд (вкладки, недавние сессии, действия, новая сессия в проекте), ⌘N новая сессия, ⇧⌘O сессии, ⇧⌘U статистика, ⌘T новая вкладка в том же проекте, ⌘W закрыть вкладку, ⌘R перезапустить вкладку (та же
сессия), ⌘1…⌘9 вкладки, ⌘J вкладка, которая ждет ответа, ⌥⌘I панель сессии, ⌃⌥Space показать приложение из любого другого.

Сочетания меняются в Настройки → Горячие клавиши: нажать на клавишу в строке и набрать новое, Esc отменяет,
Delete убирает. Занятое другим действием или системой сочетание не принимается. Свои сочетания лежат в
UserDefaults (`shortcuts`), меню читает их из `ShortcutStore` в `Shortcuts.swift` и меняется сразу. ⌘Q, ⌘, и
⌘1…9 не меняются.

## Браузер через proxy

Вкладкам через proxy приложение ставит `BROWSER` на свой помощник
`~/Library/Application Support/Agentmeister/bin/agentmeister-browse`. Claude Code открывает страницы через
`BROWSER`, поэтому вход, OAuth для MCP и другие страницы от агента грузятся во встроенном браузере, который ходит
в сеть через тот же mihomo. Помощник передает ссылку приложению через `agentmeister://browse?url=`. Без mihomo
браузер ничего не грузит, обхода напрямую нет, кроме localhost, куда агент принимает ответ входа. Ссылки по клику
из вкладки входа тоже идут туда. Ссылку по клику из обычной вкладки через proxy приложение по умолчанию
предлагает открыть в окне Agentmeister, в отдельном профиле Chrome через mihomo или в браузере системы, выбор
можно запомнить (`LinkPlace.swift`). Переключается в Настройки → Proxy.

Codex открывает страницу входа сам, мимо `BROWSER`. Для него ссылку из вкладки входа нужно нажать.

`SPIKE.md` хранит результаты проверки SwiftTerm.
